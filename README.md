# GCP Terraform + Ansible Baseline (Dev / Prod)

A beginner-friendly but production-style DevOps project:

- **Terraform** provisions a VPC, firewall rules, and a Compute Engine VM on **Google Cloud**, for two isolated environments (**dev** and **prod**), using reusable modules and remote state in a GCS bucket.
- **Ansible** configures the VM: **hardens SSH**, installs **fail2ban** and **automatic security updates**, and deploys **Nginx** with an environment-specific web page.
- Terraform **auto-generates the Ansible inventory**, so the two tools are wired together.
- **GitHub Actions** runs `terraform fmt/validate` and `ansible-lint` on every push.

See [docs/architecture.md](docs/architecture.md) for the diagram and design decisions.

```
│   ├── bootstrap/               # Run once: creates the GCS state bucket
│   ├── modules/
│   │   ├── network/             # VPC, subnet, firewall rules
│   │   └── compute/             # VM, static IP, service account
│   ├── main.tf                  # Calls modules + writes Ansible inventory
│   ├── variables.tf / outputs.tf / providers.tf / backend.tf
│   └── envs/                    # dev & prod variables and backend config
└── ansible/
    ├── ansible.cfg
    ├── site.yml                 # Main playbook
    ├── inventory/{dev,prod}/    # hosts.ini generated by Terraform
    └── roles/
        ├── baseline/            # SSH hardening, fail2ban, auto-updates
        └── nginx/               # Nginx + templated index page
```

## Prerequisites

- A GCP project with **billing enabled** (free trial credits work)
- Tools: `gcloud` CLI, `terraform` >= 1.5, `ansible` >= 2.14
- An SSH key pair (create one if needed):
  ```bash
  ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -N ""
  ```
- Authenticate and enable the Compute and Storage APIs:
  ```bash
  gcloud auth login
  gcloud auth application-default login
  gcloud config set project YOUR_PROJECT_ID
  gcloud services enable compute.googleapis.com storage.googleapis.com
  ```

## Step-by-step usage

### 1. Create the state bucket (one time)

```bash
cd terraform/bootstrap
terraform init
terraform apply -var="project_id=YOUR_PROJECT_ID"
```

### 2. Edit the config files

Replace `your-project-id` in:

- `terraform/envs/dev.tfvars` and `terraform/envs/prod.tfvars`
- `terraform/envs/dev.backend.hcl` and `terraform/envs/prod.backend.hcl` (bucket = `YOUR_PROJECT_ID-tfstate`)

Also set `ssh_source_ranges` to your own IP (find it with `curl ifconfig.me`), e.g. `["203.0.113.5/32"]`.

### 3. Deploy the dev environment

```bash
cd terraform
terraform init -backend-config=envs/dev.backend.hcl -reconfigure
terraform plan  -var-file=envs/dev.tfvars
terraform apply -var-file=envs/dev.tfvars
```

This creates the infrastructure and writes `ansible/inventory/dev/hosts.ini`.

### 4. Configure the server with Ansible

```bash
cd ../ansible
ansible all -i inventory/dev/hosts.ini -m ping                        # test connection
ansible-playbook -i inventory/dev/hosts.ini site.yml --check --diff   # dry run
ansible-playbook -i inventory/dev/hosts.ini site.yml                  # apply
```

Open the URL from `terraform output web_url` in your browser.

### 5. Prove idempotency

Run the playbook a second time. The recap should show `changed=0`.

### 6. Deploy prod

```bash
cd ../terraform
terraform init -backend-config=envs/prod.backend.hcl -reconfigure
terraform apply -var-file=envs/prod.tfvars

cd ../ansible
ansible-playbook -i inventory/prod/hosts.ini site.yml
```

> Always run `terraform init -backend-config=... -reconfigure` when switching environments so you never apply to the wrong state.

## Verify the hardening

```bash
ssh -i ~/.ssh/id_ed25519 ansible@EXTERNAL_IP
sudo sshd -T | grep -E "permitrootlogin|passwordauthentication"   # both should be 'no'
sudo systemctl status fail2ban
sudo fail2ban-client status sshd
cat /etc/apt/apt.conf.d/20auto-upgrades
```

## Clean up (avoid charges!)

```bash
cd terraform
terraform init -backend-config=envs/dev.backend.hcl -reconfigure
terraform destroy -var-file=envs/dev.tfvars

terraform init -backend-config=envs/prod.backend.hcl -reconfigure
terraform destroy -var-file=envs/prod.tfvars
```

The state bucket is not deleted automatically (`force_destroy = false`). Remove it manually when finished.

**Cost note:** `e2-micro` / `e2-small` VMs plus a static IP cost only a few dollars per month if left running. Set a **budget alert** in the GCP console and destroy resources when done.

## Troubleshooting

| Problem | Fix |
|---|---|
| `Permission denied (publickey)` | Check the public/private key paths match; wait ~1 min after VM creation |
| Ansible timeout | `ssh_source_ranges` doesn't include your current IP (it may have changed) |
| `API not enabled` error | Run the `gcloud services enable ...` command above |
| Locked out after SSH hardening | Keep a second SSH session open while testing; `validate:` prevents broken configs |
| Backend bucket error | Bucket name in `*.backend.hcl` must match the bootstrap output |
